Overview

Dataset Overview

TrustXQoE captures the complete end-to-end streaming delivery chain, from the origin server to the selected edge, access/backhaul network behavior, client playback state, and human QoE feedback.

The TrustXQoE Dataset is a large-scale, human-annotated, end-to-end cross-layer video streaming dataset designed for trustworthy and interpretable Quality of Experience modeling. It was collected using a controlled video streaming testbed that integrates Content Delivery Network and Software-Defined Networking components, enabling flexible content delivery, edge-based streaming, and dynamic network control.

The testbed consists of 1 content server, 8 edge nodes, and 9 concurrent users. Each user streamed 10 video sessions, producing diverse streaming scenarios under dynamically varying network conditions. For each user, the dataset includes more than one possible network path and records the edge node and delivery path used for each streamed video. The dataset contains more than 58,658 temporally aligned samples and MOS labels ranging from 0 to 5.

The dataset integrates synchronized measurements from multiple layers of the video delivery chain, including client playback behavior, HLS segment download characteristics, playback events, edge server metrics, origin server metrics, access network metrics, backhaul network metrics, topology metadata, edge-node information, path information, and MOS/QoE labels.

The metadata, documentation, and full processed data will be made available soon. Until the release is finalized, all external dataset, DOI, and repository links are marked as Coming soon.

Collection

How the Dataset Was Collected

The dataset was collected in a controlled SDN-CDN video streaming environment with concurrent users and dynamically changing network conditions.

Experimental process

Multiple HLS clients streamed video content through edge servers connected to an origin server. During the experiments, bandwidth variability, latency fluctuations, congestion events, edge-selection changes, and path-level performance variations were introduced to emulate realistic operating conditions.

For each user and each video session, the testbed can use more than one delivery path. The dataset records the edge node and the corresponding access/backhaul path used for each video, enabling path-aware QoE analysis, edge trust evaluation, and comparison of alternative routing and delivery decisions.

Client-side measurements were sampled at fine temporal granularity and include buffer level, bitrate, resolution, playback state, dropped frames, segment download information, stalls, playback events, and bandwidth estimation. Edge and origin servers logged request-level delivery information, while packet captures were analyzed to extract network-level QoS metrics.

Human participants interacted with the streaming system and provided subjective QoE feedback in the form of MOS labels. All collected measurements were synchronized into a cross-layer, time-aligned dataset.

Synchronized collection layers

The collection process focuses on aligning measurements from the video player, the edge delivery layer, and the network paths into one time-indexed dataset.

Client playback layer
Buffer level, bitrate, resolution, stalls, playback events, dropped frames, and estimated bandwidth.
Segment delivery layer
HLS segment requests, segment size, download time, throughput, quality level, and request identifiers.
Edge and origin layer
Edge response behavior, origin delivery behavior, cache-related information, response timing, and bytes delivered.
Network layer
Access and backhaul throughput, delay, jitter, RTT, packet loss, retransmissions, and path-level behavior.
QoE annotation layer
MOS labels and subjective QoE feedback aligned with the streaming and network measurements.

Applications

What You Can Do With the Dataset

TrustXQoE can support machine learning, networking, streaming, zero-touch networking, edge selection, path selection, adaptive bitrate optimization, and explainable AI research.

QoE Classification

Train models to classify user experience into MOS classes and detect poor, acceptable, good, or excellent streaming states.

QoE Forecasting

Predict future QoE degradation before it happens, enabling proactive control of delivery decisions.

Edge Selection

Study which edge node should serve each user or video based on latency, throughput, stability, and QoE impact.

Path Selection

Compare alternative access/backhaul paths and learn how delivery paths affect QoS and perceived video quality.

Zero-Touch Networking

Develop closed-loop automation policies that observe network/streaming state and adapt the system without manual intervention.

Adaptive Bitrate Optimization

Evaluate ABR strategies using cross-layer signals such as buffer level, throughput, segment load time, and network congestion.

Anomaly and Degradation Detection

Detect stalls, QoE drops, abnormal delay, packet loss spikes, and unstable edge/path behavior.

Explainable AI

Use feature-attribution methods to identify which client, edge, origin, and network features drive QoE predictions.

Trust-Aware Networking

Model trust in edge nodes, network paths, and AI decisions for adaptive and reliable video delivery.

Edge Caching Analysis

Analyze how edge behavior, response latency, cache performance, and delivery stability affect streaming quality.

Network QoS Analysis

Study how throughput, delay, jitter, packet loss, RTT, and retransmissions relate to MOS degradation.

Benchmarking ML Models

Use the dataset as a benchmark for supervised learning, time-series modeling, graph-based learning, and cross-layer prediction.

Features

Full Feature Set

TrustXQoE includes features from the complete end-to-end streaming pipeline, organized by column prefixes.

Feature GroupPrefixDescription
Origin server featuresORIGIN_Origin/content server request and response metrics, including request handling, response behavior, transferred bytes, and server-side delivery information.
Edge server featuresEDGE_Edge node request handling, cache behavior, response latency, selected edge, delivery path, and time-to-last-byte.
Event-based featuresEV_Client playback events such as play, pause, stall, seek, bitrate switch, buffer events, errors, and state transitions.
Segment-based featuresSEG_HLS segment download statistics, including request time, response time, segment size, download duration, throughput, quality level, and request identifiers.
Time-series playback featuresTS_Continuous client-side measurements such as buffer level, bitrate, resolution, playback rate, dropped frames, total frames, bandwidth estimation, and playback timeline.
Access network featuresACCESS_Network metrics between the client and edge server, including throughput, goodput, packet loss, delay, jitter, RTT, retransmissions, and path behavior.
Backhaul network featuresBACKHAUL_Network metrics between the edge server and origin server, including throughput, goodput, packet loss, delay, jitter, RTT, retransmissions, and delivery-path performance.
QoE label featuresmos, qoe, feedbackHuman-annotated QoE feedback, including MOS class, QoE label, and optional subjective feedback.
Path and edge metadataPATH_, EDGE_Selected edge node, available paths, selected path per video, and routing/topology context for edge selection and path-aware analysis.
ORIGIN_

Origin Server Features

Request status, response timing, bytes sent, requested video path, content type, request identifier, and origin-side delivery behavior.

EDGE_

Edge Server Features

Selected edge server, edge response time, time-to-last-byte, cache behavior, requested content path, bytes delivered, and edge-side request status.

EV_

Event-Based Features

Play, pause, stall, rebuffering, bitrate switch, level switch, seeking, playback error, buffer warnings, playback start, and playback end events.

SEG_

Segment-Based Features

Segment URL/path, size, duration, request time, first byte time, load time, download time, throughput, quality level, segment number, and request identifier.

TS_

Time-Series Playback Features

Playback time, buffer level, selected bitrate, estimated bandwidth, video width/height, playback rate, dropped frames, total frames, quality level, and FPS.

ACCESS_

Access Network Features

Client-edge throughput, goodput, packet counts, loss rate, one-way delay, jitter, RTT, retransmissions, out-of-order packets, direction, and timestamps.

BACKHAUL_

Backhaul Network Features

Edge-origin throughput, goodput, loss, delay, jitter, RTT, retransmissions, out-of-order packets, and backhaul delivery-path behavior.

PATH_ / EDGE_

Path and Edge Selection Metadata

Available paths per user, selected edge node, selected path for each video, topology identifiers, and routing context for path-aware analysis and edge selection.

Labels

QoE and Metadata

MOS class, QoE label, feedback, client identity, edge identity, IP/path information, session timing, and wall-clock alignment columns.

Labels

MOS / QoE Label Description

The dataset includes human-annotated QoE labels represented using MOS values from 0 to 5. These labels can be used as targets for QoE classification, regression, forecasting, degradation detection, trust-aware decision making, and explainable AI analysis.

MOS ClassInterpretation
0Very poor quality
1Poor quality
2Fair quality
3Acceptable quality
4Good quality
5Excellent quality

Cross-layer design

The strength of TrustXQoE is its cross-layer structure. Instead of focusing only on client-side playback metrics or only on network QoS metrics, the dataset combines information from the full streaming delivery chain.

Origin Server ↓ Backhaul Network ↓ Edge Server ↓ Access Network ↓ Client Video Player ↓ MOS / QoE Feedback
